## Automated and local integration checks

Use the pinned Node 22.23.5 and PostgreSQL server tools (`initdb`, `postgres`, `pg_ctl`, `createdb`, and `pg_isready`) from a clean workspace checkout. Install the lockfile first with `npm ci --legacy-peer-deps`; build the provider before typechecking dependent workspaces, then build the Medusa Backend/Admin:

```sh
npm run build
npm run typecheck
npm test
node scripts/medusa.mjs build
npm pack --workspace medusa-plugin-encvoy-id --dry-run
```

`npm test` runs the protocol, Admin-request, state-store, and PostgreSQL tests together. It initializes a temporary local PostgreSQL cluster under the operating system's temp directory, binds only to `127.0.0.1` on a dynamically selected free port, runs the suite against synthetic test values, stops the server, and removes the data directory afterward. It does not use the Medusa development database or Docker. The runner handles normal completion, test failure, and interruption; if it cannot stop PostgreSQL safely, it leaves the temporary data directory for inspection instead of deleting a live cluster. The command fails rather than silently skipping the PostgreSQL checks if the PostgreSQL server tools are unavailable. On Windows, add the PostgreSQL `bin` directory containing `initdb.exe`, `postgres.exe`, `pg_ctl.exe`, `createdb.exe`, and `pg_isready.exe` to `PATH` before running it.
