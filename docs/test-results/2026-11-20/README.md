## Что исправлено и как проверено

- Временный PostgreSQL тестового раннера больше не создаёт Unix-сокеты: все его клиенты используют TCP loopback. При неудачном запуске выводятся последние 60 строк журнала PostgreSQL. Локально исходный сбой воспроизведён с недоступным каталогом сокетов; после исправления тот же сценарий выполнил все тесты. Исходный CI не сохранил журнал сервера в выводе, поэтому точная причина именно первоначального сбоя непосредственно не установлена.
- Следующий запуск CI прошёл PostgreSQL, но обнаружил `UNKNOWN` в диагностике недоступного OIDC-сервера. Добавлена точная разрешённая классификация `UND_ERR_SOCKET`. Новый тест с реальным обрывом HTTP-соединения падал до исправления и прошёл после него. Ответ клиенту остаётся `provider_unavailable`; тест проверяет фиксированную структуру диагностики и отсутствие секретов.
- Итоговый локальный прогон также дал 62/62, без пропусков, на Node.js 22.23.5 и PostgreSQL 16.15. Сборка и typecheck прошли. В одной временной установке `npm ls` выявил invalid `ajv-formats`/`pg`; повторный `npm ci` из неизменённого lockfile дал чистый `npm ls`, затем снова прошли 62/62 теста. Причина различия этих локальных установок не установлена. В итоговом GitHub CI проверка дерева зависимостей прошла.
